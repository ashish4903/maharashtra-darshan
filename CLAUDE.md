# Maharashtra Darshan

React (Vite) app for exploring Maharashtra: regions → districts → talukas, places to visit and food to try. Public repo, deployed to GitHub Pages.

## Commands

- `npm run dev`: dev server
- `npm test`: Vitest (tests sit next to the code as `*.test.js(x)`)
- `npm run lint`, `npm run build`
- `npm run suggest -- <District>`: candidate places from Wikipedia (writes ignored suggestions.json)
- `npm run og-image`: redraws public/og-image.svg (convert it to PNG, see the script)
- `npm run data`: rebuilds `src/data/maharashtra.json` from Wikidata/Wikipedia (needs network)

## Where things are

- `data/curated.json`: the only hand-edited data: regions, renames, knownFor, places, foods, circuits, festivals, extras, seasons, trails
- `scripts/build-data.mjs`: fetches and checks the data, then writes the JSON
- `src/data/maharashtra.json`: **generated, ~225 KB**. Never edit by hand
- `src/data/outline.json`: generated by `npm run outline` (Natural Earth state border)
- `src/lib/catalogue.js`: all data access (components never import the JSON)
- `src/lib/geo.js`: map projection, distances, nearest places
- `src/lib/planner.js`: getaway planner (scoring, compact picks, route from a start)
- `src/lib/tripWeather.js`: per-day trip forecasts (one Open-Meteo request, each day's first stop), rain/heat warnings on outdoor days and the drier-day swap
- `src/lib/speech.js`: listen mode (browser speech only: voice choice with Marathi → Hindi → English fallback, sentence chunks, place and trip-day scripts, one shared player); `useWikiSummary.js` loads the summary for both display and listening
- `scripts/trails.mjs`: history trails. Each stop's wording is ours, but every evidence group must appear in ONE sentence of the place's article, a listed source or the trail's article, and every year shown must be in a matched sentence. `npm run trails` re-checks and updates only the trails; `npm run data` checks them too
- `scripts/commons.mjs` (`npm run commons`): adds only each place's Commons category (Wikidata P373) for the gallery; `npm run data` adds it too
- `src/lib/trip.js`: route ordering, day split, Google Maps directions links
- `src/lib/route.js`: hash routes `#/`, `#/region/<id>`, `#/district/<Wikidata id>`, `#/place/<Wikidata id>`, `#/circuit/<id>`, `#/trail/<id>[/<stop>]`, `#/festivals`, `#/seasons`, `#/plan`, `#/trip`, `#/trip/<ids>` (shared)
- `src/lib/i18n.js`: all interface text in English and Marathi; use `useLang()` (`t`, `name`, `kind`) in components, and never hard-code visible text. A test fails if a Marathi translation is missing
- `src/components/TripProvider.jsx` + `src/lib/useTrip.js`: saved places (localStorage only)
- Runtime network calls: only Wikipedia's REST summary (`WikiSummary.jsx`), Commons images, the Commons category search for the place gallery (`src/lib/commons.js`, category name only, licence-filtered, `utm_*` stripped) and Open-Meteo forecasts (`Weather.jsx` and `TripPlan.jsx`, coordinates only). Google Maps appears only as plain search links (`mapsSearchUrl`); never scrape, copy or store Google ratings, and never add a Maps API key without the owner's approval. Keep it that way: no trackers or analytics
- `src/components/`: one small component per file
- `src/index.css`: all styles, mobile-first; each region colour is a CSS variable

## Saving tokens

- Don't read `src/data/maharashtra.json`, `package-lock.json`, `node_modules/` or `dist/`. Query the data with a node one-liner instead, e.g. `node -e "const d=require('./src/data/maharashtra.json'); console.log(d.places.length)"`
- Read `data/curated.json` only when changing data; search it with grep first.
- To add data, use the `add-place-or-food` skill.

## Rules

- **No invented data.** Every entry needs a source that `npm run data` verifies: its own Wikipedia article, or (in `extras`) an official district site (`*.gov.in`/`*.nic.in`) or a Wikipedia article that mentions it. Photos only from Wikimedia Commons with a free licence (never copied from other sites). If a check fails, drop or fix the entry; never weaken the check.
- Plain React + CSS, no UI library unless asked. Mobile-first. One component per file.
- **Security:** never commit secrets, tokens, `.env` files or personal data. The app needs no keys. Don't read files outside this folder, or any config or credential files, without asking the owner first.
- Commit author must be the GitHub noreply address. New branch + PR per change. Add a line under "Unreleased" in `CHANGELOG.md` (keep one Added / Changed / Fixed block each). Release only when the owner asks: move Unreleased into a new version section and raise package.json `version`; CI publishes the GitHub Release.
